# Améliorations code — AEMPO-TOGO

Liste des améliorations possibles sans modifier le design actuel.
Classées par priorité décroissante.

## Bloc 1 — Prioritaires (impact fort, effort faible)

### 1. Centraliser les routes
**Fichiers :** `Header.tsx:9-12`, `Footer.tsx:12-32`
Créer `app/lib/routes.ts` avec les routes `/about`, `/news`, `/offices`, `/contact` pour éviter les divergences et fautes de frappe entre Header et Footer.
```ts
export const ROUTES = { about: "/about", news: "/news", offices: "/offices", contact: "/contact" } as const;
```

### 2. Tokens de couleur Tailwind
**Fichiers :** `globals.css:8-14` + tous les composants
Définir les couleurs du projet dans `@theme inline` pour remplacer les valeurs hex hardcodées (`bg-[#0e3b23]`, `text-[#1c4b31]`, etc.).
```css
@theme inline {
  --color-brand-darkest: #0e3b23;
  --color-brand-dark: #1c4b31;
  --color-brand-mid: #448b62;
  --color-brand-light: #357a55;
  --color-brand-surface: #eef6f0;
  --color-accent-light: #fdf4db;
  --color-cta: #3d8b61;
  --color-banner: #103a22;
  --color-footer-bg: #eff7f1;
  --color-footer-bottom: #4ea977;
}
```

### 3. Typage des données
**Fichiers :** `page.tsx:7-82`, `Header.tsx:8-13`, `Footer.tsx:8-42`, `JournalSection.tsx:7-15`
Créer `app/lib/types.ts` avec les interfaces `JournalItem`, `Partner`, `CardData`, `NavLink`, `FooterLinkSection`, `SocialLink` pour typer toutes les structures de données actuellement non typées.

### 4. `lang="en"` → `"fr"`
**Fichier :** `layout.tsx:44`
Le site est en français. Changer `lang="en"` en `lang="fr"` (accessibilité screen-reader + SEO).

### 5. Accessibilité : aria-labels manquants
**Fichiers :** `JournalSection.tsx:47-58`, `Footer.tsx:62-65`
- Boutons flèches journal : ajouter `aria-label="Défiler à gauche"` / `aria-label="Défiler à droite"`
- Champ email newsletter : ajouter `<label>` caché ou `aria-label="Adresse email"`

### 6. Extraire `CONTAINER_CLASS` partagé
**Fichiers :** `Hero.tsx:8`, `Footer.tsx:45`
La classe `"mx-auto max-w-[1440px] px-6 lg:px-12"` est dupliquée dans Hero et Footer. La centraliser dans `app/lib/constants.ts`.

### 7. Extraire `ScrollFadeOverlay`
**Fichier :** `JournalSection.tsx:63-70`
Les deux divs de fondu (gauche/droite) sont quasi-identiques. En faire un composant réutilisable recevant une prop `side: "left" | "right"`.

### 8. `style={{ opacity }}` → toggle classe CSS
**Fichier :** `JournalSection.tsx:64-70`
Remplacer le `style={{ opacity: isAtStart ? 0 : 1 }}` par un toggle de classe `opacity-0` / `opacity-100` pour éviter les recalculs de layout à chaque pixel de scroll.

## Bloc 3 — Tranquilles (nice to have)

Ajouter une page 404 personnalisée et un error boundary global pour éviter le fallback Next.js par défaut.

### 17. États de chargement
**Fichier :** `app/loading.tsx` (à créer)
Ajouter un `loading.tsx` au niveau racine pour les futures pages avec chargement de données.

### 18. Réorganiser les composants en sous-dossiers
**Dossier :** `app/components/`
Grouper par rôle : `layout/` (Header, Footer), `sections/` (Hero, JournalSection), `ui/` (JournalCard, StatsCard, ThemeToggle).

### 19. Extraire les données mock
**Fichiers :** `page.tsx:7-82`
Déplacer `CARDS_DATA`, `JOURNAL_DATA`, `PARTNERS` dans `app/data/` pour séparer données et présentation.

### 20. Unifier les imports
**Fichiers :** `Hero.tsx:6`, `ThemeToggle.tsx:4`, `about/page.tsx:1`
- Icônes : utiliser `@phosphor-icons/react/dist/ssr` partout (ThemeToggle utilise `@phosphor-icons/react`)
- Alias : utiliser `@/` partout (about/page.tsx utilise `@/app/components/Hero`)

### 21. Typer `imagePosition` en union
**Fichier :** `Hero.tsx:18`
Remplacer `imagePosition?: string` par `imagePosition?: "object-center" | "object-top" | "object-bottom" | "object-left" | "object-right" | "object-left-top" | "object-left-bottom" | "object-right-top" | "object-right-bottom"`.

### 22. `imageAlt` dynamique dans Hero
**Fichier :** `Hero.tsx:53`
Le `alt` de l'image Hero est hardcodé (`"AEMPO Togo Students"`). Ajouter une prop `imageAlt?: string` pour que chaque page puisse décrire son image.
